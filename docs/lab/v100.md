# Lab profile: NVIDIA V100

This is the **Go training box**. Volta, 16 or 32 GB HBM2, mature CUDA. First-generation tensor cores: **FP16 yes, BF16 no**.

## What is fast

| Job | Engine | Config |
|-----|--------|--------|
| Train / fine-tune | GoMLX XLA CUDA | `GOMLX_BACKEND=xla:cuda` |
| ONNX pipelines | Hugot ORT CUDA | `NewORTSession` + `options.WithCuda` |
| GGUF generate / embed | llama.cpp CUDA | `-ngl 999` |

If `quikaitools doctor --profile auto` prints `gomlx-go` or `cpu`, CUDA is not visible. Fix the driver/toolkit before debugging models.

## Install

1. NVIDIA driver + **CUDA 12.x**. Hugot ORT GPU builds want **cuDNN 9.x** as well.
2. Go 1.27+.
3. GoMLX XLA plugin (auto-installs on first run into `~/.local/lib/go-xla`, or set `GOMLX_NO_AUTO_INSTALL=1` and vendor it).
4. Confirm:

```bash
nvidia-smi --query-gpu=name,memory.total --format=csv
quikaitools doctor --profile auto
# expect: kind v100, train gomlx-xla-cuda, mixed_precision fp16
```

Minimal CUDA userspace that has worked for Hugot GPU (Fedora/AL2-style packages): `cuda-cudart`, `cuda-nvrtc`, `libcublas`, `libcurand`, `libcufft`, `libcudnn9-cuda-12`.

## Memory discipline

- **16 GB:** full-rank 7B is not the plan. LoRA, then QLoRA, gradient accumulation, activation checkpointing (GoMLX already has a checkpoint API).
- **32 GB:** small full-rank or larger LoRA. Still prefer adapters; V100 is not an A100.
- Always **FP16**, never assume BF16 recipes from Ampere blog posts.

## Doctor contract

`quikaitools doctor --profile v100` is the explicit override when you are writing docs on a Mac. On the actual V100 host, `auto` should resolve to `v100` because `nvidia-smi` reports a name containing `V100`.
